# Repositorio de Proyecto: Ingeniería de Requisitos para Sistema de Gimnasio

Este directorio consolida el trabajo desarrollado a lo largo de varias etapas para la asignatura de Ingeniería de Requisitos (Universidad de Jaén). El proyecto global abarca el análisis y modelado completo para un **Sistema de Gestión de Gimnasio**.

A continuación, se detalla el contenido temático estructurado en las diferentes carpetas o secciones del repositorio:

## Estructura del Repositorio

### 1. Modelado Orientado a Objetivos
Esta carpeta contiene el análisis inicial de las intenciones, necesidades y dependencias de los involucrados en el sistema.
*   Se utiliza el framework **i-Star** para modelar las relaciones entre los distintos actores (Administrador, Usuario, Monitor, Técnico de Mantenimiento).
*   Incluye Modelos de Dependencias Estratégicas (SDM) y Modelos de Razonamiento Estratégico (SRM) detallados para cada rol.
*   Documenta en lenguaje natural y mediante plantillas los objetivos principales (Hardgoals), objetivos de calidad (Softgoals) y tareas específicas.

### 2. Especificación de Casos de Uso y Comportamiento Dinámico
Esta sección profundiza en las interacciones funcionales directas entre los usuarios y el software.
*   Presenta un diagrama unificado con la visión global de los casos de uso del sistema.
*   Detalla de forma exhaustiva los flujos de interacción (precondiciones, secuencias normales, excepciones y escenarios alternativos).
*   Se apoya en diagramas de comportamiento UML, específicamente **Diagramas de Actividad** y **Diagramas de Secuencia**, para ilustrar paso a paso la toma de decisiones y el intercambio de mensajes.

### 3. Modelo del Dominio y Estructura Conceptual
Esta carpeta alberga el análisis estructural de la información y la lógica de negocio que rige el gimnasio.
*   Muestra el proceso de extracción de requisitos mediante el análisis lingüístico de los escenarios y la técnica de observación por categorías.
*   Proporciona listas unificadas de entidades, atributos y asociaciones, respaldadas por un glosario formal de términos.
*   Culmina con un **Diagrama de Clases UML** que representa gráficamente la arquitectura conceptual del dominio.
